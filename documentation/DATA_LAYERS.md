# Data Layers: Storage & Messaging Strategy

## 1. Relational Layer (PostgreSQL)

The system uses PostgreSQL for structured, persistent metadata. Access is managed via the **Prisma ORM**.

### 1.1 Core Entities & Relations
- **User / Role / Permission:** Implements RBAC. A many-to-many relationship exists between Roles and Permissions, and Users and Roles.
- **Lab:** Logical grouping for Users and VMs.
- **VM:** Represents a Proxmox instance. Linked to a `Lab` and tracks `VMPackage` installation states.
- **Log:** Audit trail for system events, categorized by `LogType` (e.g., `VM_PROVISIONED`, `NIX_BUILD_FAILED`) and `LogSeverity`.
- **Notification:** Real-time alerts for users, integrated with the WebSocket engine.

### 1.2 Schema Design Patterns
- **CUIDs:** All primary keys utilize Collision-resistant Unique Identifiers (CUID) for distributed safety.
- **Cascading Deletes:** Deleting a `User` cascades to their `Sessions` but sets `userId` to null in `Logs` to preserve audit integrity.

## 2. Time-Series Layer (InfluxDB)

Historical performance metrics are stored in InfluxDB and queried using the **Flux** language.

### 2.1 Metric Schema
- **Bucket:** `vdi_bucket`
- **Measurements:**
    - `cpu`: Tracks `usage_active` (field) for `cpu-total` (tag).
    - `mem`: Tracks `used_percent` (field).
    - `net`: Tracks `bytes_recv` and `bytes_sent` (fields).
    - `disk`: Tracks `used_percent` (field) for the root mount.

### 2.2 Query Strategy
The Control Plane utilizes `aggregateWindow(every: 2h, fn: mean)` for dashboard trends and raw point queries for live granular views. Filters are applied based on the `host` tag, which matches the VM's `hostname`.

## 3. Message Bus (Kafka)

Kafka acts as the high-throughput ingestion layer for telemetry generated by thousands of ephemeral VMs.

### 3.1 Topic: `vm-metrics`
- **Producer:** Telegraf (running inside NixOS).
- **Consumer:** Next.js `server.ts` (using `kafkajs`).
- **Format:** JSON.
- **Data Frequency:** 10-second intervals.

### 3.2 Real-time Processing Logic
1. **Ingestion:** The `vdi-metrics-group` consumer group reads messages from the `vm-metrics` topic.
2. **Aggregation:** Messages are keyed by `host` (hostname) and stored in an in-memory `hostState` buffer.
3. **Threshold Detection:** If `cpu` or `ram` fields exceed 90% for a given host, a `RESOURCE_CRITICAL` notification is persisted to PostgreSQL and broadcast via WebSockets.
4. **WebSocket Dispatch:** The aggregated `hostState` object is emitted to all connected UI clients via the `vm-metrics-update` event.
